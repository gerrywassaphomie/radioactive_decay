# Радиоактивный распад

[![.NET build and test](https://github.com/gerrywassaphomie/radioactive_decay/actions/workflows/dotnet.yml/badge.svg?branch=main)](https://github.com/gerrywassaphomie/radioactive_decay/actions/workflows/dotnet.yml)

Веб-приложение для лабораторной работы по дисциплине «Виртуальный физический эксперимент». Приложение моделирует закон радиоактивного распада, показывает результаты расчёта и позволяет подготовить данные для дальнейшего анализа.

**Лабораторная по программе:** № 8 — «Радиоактивный распад»<br>
**Основной язык:** C#<br>
**Архитектура:** слоистая, пользовательский интерфейс — ASP.NET Core MVC<br>
**Репозиторий:** [gerrywassaphomie/radioactive_decay](https://github.com/gerrywassaphomie/radioactive_decay)

Структура решения:

```text
RadioactiveDecay.Core/        физическая модель, solver и сценарий расчёта
RadioactiveDecay.Export/      экспорт результатов в CSV и JSON
RadioactiveDecay.Web/         ASP.NET Core MVC, представления и визуализация
RadioactiveDecay.Core.Tests/  тесты модели и расчётного модуля
RadioactiveDecay.Export.Tests/ тесты CSV/JSON
```

Правила зависимостей:

- `RadioactiveDecay.Core` не зависит от веб-интерфейса и инфраструктуры;
- `RadioactiveDecay.Export` работает с результатами Core и не содержит UI;
- `RadioactiveDecay.Web` отвечает за ввод, валидацию, отображение и связывание слоёв;
- физические формулы и шаги solver не размещаются в MVC-контроллерах или представлениях.

## Запуск и проверка

### Установка SDK на Windows и macOS

Проект рассчитан на `net10.0`. Минимальный выбранный SDK — **10.0.401**;
локально проверен **10.0.402**. `global.json` допускает более новые совместимые
SDK 10.0 через `rollForward: latestFeature`.

1. Откройте [официальную страницу .NET 10](https://dotnet.microsoft.com/download/dotnet/10.0).
2. В разделе **SDK** скачайте установщик: Windows x64 для обычного ПК,
   Windows Arm64 для ARM; macOS Arm64 для Apple Silicon, macOS x64 для Intel.
   Нужен SDK, а не только Runtime.
3. Установите SDK, закройте и заново откройте PowerShell/Terminal.
4. Выполните `dotnet --list-sdks`: должна присутствовать версия 10.0.401
   или более новая совместимая 10.0.4xx. В папке проекта `dotnet --version`
   покажет SDK, выбранный с учётом `global.json`.

**Если установлен только .NET 9:** он не собирает `net10.0` (ошибка NETSDK1045).
Установите SDK 10 рядом с имеющимся SDK. Менять `rollForward` на 9.x или удалять
`global.json` для устранения ошибки не следует: это не добавляет поддержку net10.0.
Переход на другую целевую платформу требует отдельного согласования с преподавателем.

### Получение проекта

```bash
git clone https://github.com/gerrywassaphomie/radioactive_decay.git
cd radioactive_decay
```

Либо скачайте **Code → Download ZIP** и распакуйте архив. Откройте терминал
именно в каталоге с `RadioactiveDecay.sln` и `global.json`.
Если возникает MSB1003, вы находитесь не в корне решения: найдите вложенную
папку с `.sln`. Для закрытого репозитория нужен аккаунт с доступом.

### Сборка, тестирование и запуск

```bash
dotnet restore
dotnet build
dotnet test
dotnet run --project RadioactiveDecay.Web --urls http://localhost:5188
```

Откройте http://localhost:5188. Для остановки сервера нажмите Ctrl+C.
Пример: 1000 ядер, период полураспада 10 с, длительность 50 с, шаг 1 с.
При t = 10 с должно остаться 500 ядер.

При текущем составе решения ожидается 52 успешных теста: 34 Core и 18 Export,
без ошибок и пропусков. Для запуска достаточно браузера и SDK; база данных
и API-ключи не нужны. Первый restore требует доступа к NuGet.

### Проверка на GitHub

Workflow [`.NET build and test`](https://github.com/gerrywassaphomie/radioactive_decay/actions/workflows/dotnet.yml)
запускается при push и PR в main, а также вручную через Actions → Run workflow.
Он устанавливает SDK из `global.json`, затем выполняет restore, Release build
и все тесты на Windows, macOS и Linux. Результаты доступны в Actions и Checks PR.
Значок вверху показывает состояние **main**: после добавления workflow он станет
информативным после первого запуска на main. Наличие значка само по себе не
означает успех — перед merge проверьте зелёные результаты всех трёх ОС.

  approve объединяет PR и проверяет зелёный запуск на main.
- **Егор (Core):** со своего аккаунта проверяет PR тимлида и результаты 34 тестов

- **Владислав (UI):** на Windows проходит инструкцию с чистой копией проекта,
  проверяет форму, график, валидацию и скачивание CSV/JSON; со своего аккаунта
  оставляет review с фактическим результатом и версией SDK.
- **Герман:** перед повторной сдачей уточняет у преподавателя, обязателен ли
  .NET 8/9. Если обязателен, перенос платформы оформляется отдельной задачей;
  текущая инструкция и CI не заявляют совместимость с SDK 9.

Проверки участников не считаются выполненными до их реального запуска и review.

Реализованы аналитический расчёт Core, MVC-форма с серверной валидацией,
локальный SVG-график, таблица и слой Export. В Web время задаётся в секундах,
активность — в Бк. Максимум 2 000 точек за запрос, включая скачивание.

После успешного расчёта доступны кнопки «Скачать CSV» и «Скачать JSON».
Они скачивают результаты именно этого расчёта; после изменения полей сначала
нажмите «Рассчитать распад». При скачивании сервер заново проверяет параметры
и вызывает Core. Результаты, переданные клиентом, не принимаются.

- CSV: UTF-8 без BOM, разделитель — запятая, десятичная точка независимо от локали,
  строки CRLF, столбцы `TimeSeconds,RemainingQuantity,ActivityBq`.
- JSON: UTF-8, числовые свойства, исходные `parameters` и массив `points`, camelCase.
- Пустой список даёт CSV с заголовком / JSON с пустым массивом. Null и неконечные
  числа отклоняются экспортёрами с исключениями аргументов.

Core и UI объединены отдельными PR участников. Интеграция и экспорт должны
пройти независимый review Егора или Владислава перед объединением.

## Правила GitHub

- `main` всегда должен собираться командой `dotnet build`;
- каждая задача выполняется в отдельной feature-ветке;
- автор PR отвечает за код в своей зоне;
- тимлид проводит review и выполняет merge после как минимум одного approve;
- в описании PR указываются номер лабораторной, роль автора, выполненная работа и результаты проверок;
- `bin/`, `obj/`, секреты и локальные настройки в репозиторий не добавляются.

Примеры веток для текущей лабораторной:

- `lab-8/core-radioactive-decay`;
- `lab-8/web-interface`;
- `lab-8/integration`;
- `lab-8/docs-team-roles`.
